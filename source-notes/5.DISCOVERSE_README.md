## 🎯 核心问题与答案

### Q: 用户拖动 mocap 目标时，到底发生了什么？

**A: 完整链路**:
```
1. 用户拖动 → mj_data.mocap_pos/quat 更新
2. SE3 变换 → mink.SE3.from_mocap_name()
3. IK 求解 → mink.solve_ik() (QP优化)
4. 迭代收敛 → configuration.integrate(dq, dt)
5. 关节命令 → mj_data.ctrl = q_target
6. 物理仿真 → mujoco.mj_step() × 4
7. 渲染显示 → viewer.sync()
```

**关键时序**:
- 125 Hz 主循环 (8ms/帧)
- 500 Hz 物理仿真 (2ms)
- 1-5ms IK 求解 (平均 10 次迭代)

---

### Q: IK 求解器的数学原理是什么？

**A: QP 优化问题**:
```
minimize: ||J*dq - v_target||² + λ*||dq - dq_posture||²
subject to: q_min ≤ q+dq*dt ≤ q_max
            dq_min ≤ dq ≤ dq_max
```

- `J`: 雅可比矩阵 (6×n)
- `dq`: 关节速度 (待求解)
- `v_target`: 末端期望速度
- 求解器: `quadprog` (积极集法)

---

### Q: 如何保证实时性？

**A: 多层保障**:
1. **固定迭代次数**: 最多 10 次 → 可预测延迟
2. **早停策略**: 误差 < 阈值立即返回
3. **高效求解器**: quadprog/daqp, O(n³) 但 n 很小
4. **帧率控制**: sleep() 保证 125 Hz 稳定

**时间预算** (8ms/帧):
- IK: ~2ms (10 迭代 × 0.2ms)
- 仿真: ~2ms (4 步 × 0.5ms)
- 渲染: ~3ms
- 余量: ~1ms
