## 一、自动化任务执行系统

### 1.1 对比：交互式 vs 自动化

| 维度 | 交互式 IK 控制 | 自动化任务执行 |
|------|---------------|---------------|
| **入口文件** | `mocap_ik_manipulator.py` | `tasks_airbot_play/place_coffeecup.py` |
| **用户输入** | 实时拖拽 mocap 目标点 | 预编程状态机 |
| **运动规划** | Mink QP 实时求解 | AirbotPlayIK 解析解 + 轨迹插值 |
| **应用场景** | 调试、演示、遥操作 | 数据采集、批量仿真 |
| **控制频率** | 125Hz 实时响应 | 状态机驱动（可变） |

### 1.2 状态机架构

```
┌─────────────────────────────────────────────────────────────┐
│                    SimpleStateMachine                        │
├─────────────────────────────────────────────────────────────┤
│  状态转移逻辑：                                               │
│    IDLE → GRASP → LIFT → MOVE → PLACE → RELEASE → SUCCESS   │
│                                                              │
│  每个状态：                                                   │
│    - enter(): 状态初始化（设置目标位姿）                       │
│    - step(): 单步执行（检查完成条件）                          │
│    - exit(): 状态清理                                        │
└─────────────────────────────────────────────────────────────┘
```

**关键代码**（`place_coffeecup.py:45-60`）：

```python
class PlaceCoffeeCupTask(AirbotPlayTaskBase):
    def __init__(self):
        # 10 个状态：IDLE, MOVE_TO_GRASP, GRASP, ...
        self.state_machine = SimpleStateMachine([
            IdleState(), MoveToGraspState(), GraspState(),
            LiftState(), MoveToPlaceState(), PlaceState(),
            ReleaseState(), RetreatState(), SuccessState(), FailState()
        ])
    
    def step(self):
        # 更新物理仿真
        super().step()
        # 执行当前状态逻辑
        self.state_machine.step(self)
```

### 1.3 Domain Randomization（域随机化）

**目的**：生成多样化训练数据，提升策略泛化能力。

**随机化维度**（`place_coffeecup.py:23-42`）：

```python
def domain_randomization(self):
    # 1. 物体位置随机化
    cup_pos = self.object_pose("coffeecup")
    cup_pos[:2] += np.random.uniform(-0.05, 0.05, 2)  # XY 平面 ±5cm
    
    # 2. 桌面高度随机化
    self.random_table_height("table", ["coffeecup"])  # ±3-7cm
    
    # 3. 纹理随机化
    self.random_table_texture()  # 从纹理库随机选择
    
    # 4. 材质随机化
    self.random_material("coffeecup", random_color=True)  # 镜面反射、颜色
    
    # 5. 光照随机化
    self.random_light()  # 光源位置、方向、颜色、开关状态
```

**效果**：每次 reset 生成不同的场景配置，单个任务可生成数千种变体数据。

### 2.3 IK 求解器切换

不同机器人使用不同 IK 实现：

| 机器人 | IK 实现 | 算法类型 |
|--------|---------|---------|
| AIRBOT Play | `AirbotPlayIK` | 解析解（6-DOF 封闭解） |
| UR5e / Panda | Mink + `pink` | 数值解（QP 优化） |
| MMK2 | `MMK2IK` | 解析解（双臂协同） |

**AirbotPlayIK 特点**（`airbot_play_ik.py:24-73`）：

```python
def inverseKin(self, pos, ori, ref_q=None):
    """
    解析求解 AIRBOT Play 6-DOF IK
    
    数学原理：
    1. 几何解耦：将末端位姿分解为肩部、肘部、腕部
    2. 多解枚举：2^3 = 8 组候选解（肘部上/下、腕部翻转）
    3. 关节限位筛选：保留在 joint_range 内的解
    4. 最优解选择：选择与 ref_q 距离最近的解（避免抖动）
    
    优点：
    - 计算速度 <0.1ms（比 QP 快 20-50 倍）
    - 无需迭代，保证实时性
    
    缺点：
    - 仅适用于 6-DOF 串联机械臂
    - 无法处理避障、关节速度约束
    """
```

## 三、3D Gaussian Splatting 渲染系统

### 3.1 渲染架构对比

DISCOVERSE 支持两种渲染模式：

| 模式 | 底层引擎 | 适用场景 | 渲染速度 |
|------|---------|---------|---------|
| **MuJoCo 原生渲染** | OpenGL | 调试、IK 控制 | ~3ms/frame |
| **3DGS 渲染** | CUDA Gaussian Splatting | 高保真数据采集 | ~10-20ms/frame |

### 3.2 3DGS 工作流程

```
┌─────────────────────────────────────────────────────────────┐
│  1. 场景重建（离线）                                          │
│     相机标定 → 多视角采集 → 3DGS 训练 → .ply 模型             │
│                                                              │
│  2. 仿真集成（在线）                                          │
│     MuJoCo 物理 → 物体位姿 → 3DGS 渲染 → RGB-D 图像           │
└─────────────────────────────────────────────────────────────┘
```

**生成测试 3DGS**（`generate_3dgs.py:34-87`）：

```python
def generate_ribbon(filename: str, color=(0.0, 0.5, 1.0)):
    """
    生成程序化 3DGS 模型（用于测试）
    
    数据结构：
    - xyz: 高斯中心位置 (N, 3)
    - rots: 旋转四元数 (N, 4)
    - scales: 各向异性尺度 (N, 3)
    - opacity: 透明度 (N,)
    - shs: 球谐函数系数 (N, 3*(degree+1)^2)
    """
    xyz = sample_points_on_surface()
    data = GaussianData(xyz, rots, scales, opacity, shs)
    save_ply(data, filename)
```

## 五、真实机器人部署

### 5.1 Sim-to-Real 差异

| 组件 | 仿真环境 | 真实环境 |
|------|---------|---------|
| **物理引擎** | MuJoCo | N/A（真实物理） |
| **状态反馈** | `mj_data.qpos/qvel` | CAN 总线 / ROS2 Topic |
| **控制输出** | `ctrl_joint_position` | `arm_sdk.set_target_pos()` |
| **视觉输入** | `renderer.render()` | RealSense / USB 相机 |

### 5.2 部署改造要点

**替换控制器**（`mocap_ik_manipulator.py` → 真实控制）：

```python
# 仿真版本
class SimulatorController:
    def step(self, target_qpos):
        self.mj_data.ctrl[:] = target_qpos
        mujoco.mj_step(self.mj_model, self.mj_data)

# 真实版本
class RealRobotController:
    def __init__(self):
        from arm_sdk import AirbotPlaySDK
        self.sdk = AirbotPlaySDK(port="/dev/ttyUSB0")
    
    def step(self, target_qpos):
        self.sdk.set_joint_positions(target_qpos)
        time.sleep(0.008)  # 125Hz 控制频率
```

**状态读取改造**：

```python
# 仿真
qpos = self.sensor_joint_qpos[:]

# 真实
qpos = self.sdk.get_joint_positions()
```

### 5.3 安全层设计

**必需的安全检查**：

1. **关节限位保护**：
   ```python
   if np.any(qpos < joint_limits[0]) or np.any(qpos > joint_limits[1]):
       emergency_stop()
   ```

2. **速度限制**：
   ```python
   qvel = (target_qpos - current_qpos) / dt
   if np.any(np.abs(qvel) > max_velocity):
       target_qpos = current_qpos + np.clip(qvel, -max_vel, max_vel) * dt
   ```

3. **碰撞检测**：
   ```python
   if detect_collision() or force_sensor > threshold:
       stop_and_retract()
   ```

## 六、关键技术对比总结

### 6.1 IK 求解方法对比

| 方法 | 速度 | 精度 | 约束处理 | 适用场景 |
|------|------|------|---------|---------|
| **解析解** | 0.05-0.1ms | 精确 | 仅关节限位 | 标准 6-DOF 机械臂 |
| **QP 优化（Mink）** | 1-5ms | 数值误差<1mm | 支持避障、姿态权重 | 冗余机械臂、复杂约束 |
| **雅可比伪逆** | 0.2-0.5ms | 较差（累积误差） | 无 | 快速原型开发 |

### 6.2 任务执行模式对比

| 模式 | 延迟 | 灵活性 | 开发难度 | 典型应用 |
|------|------|--------|---------|---------|
| **交互式 IK** | <8ms | 高（实时调整） | 低 | 遥操作、演示 |
| **状态机** | 可变 | 中（预编程） | 中 | 重复性任务、数据采集 |
| **强化学习策略** | <5ms | 高（泛化能力） | 高 | 复杂操作、适应性任务 |

## 八、常见问题

**Q1：如何添加自定义机器人？**

A：创建 `mjcf/manipulator/robot_myrobot.xml`，继承 `RobotBase`，实现 IK 求解器。

**Q2：Domain Randomization 如何选择参数范围？**

A：遵循"最小必要扰动"原则——覆盖真实世界变化范围，但不过度随机化。

**Q3：3DGS 渲染比 MuJoCo 慢很多，如何优化？**

A：使用 LOD（Level of Detail）策略，根据相机距离动态调整高斯点密度。

**Q4：真实机器人控制抖动怎么办？**

A：添加轨迹平滑（五次样条插值）+ 低通滤波器（截止频率 20Hz）。
